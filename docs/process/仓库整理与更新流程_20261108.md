# 仓库整理与更新流程

## 1. 目录分工

根目录只保留当前线上网站需要读取的文件：

- `index.html`：网站页面入口。
- `app.js`：页面交互、导航、卡片展开和产品切换。
- `data.js`：产品、植物图鉴、成分解码和配方记录数据。
- `styles.css`、`typography.css`：页面布局与字体样式。
- `assets/`：当前版本实际使用的图片素材。
- `3d/`：精华液 3D 预览页面、模型和预览素材。
- `scripts/build-static.cjs`：根据数据文件更新页面中的静态内容。
- `.github/workflows/pages.yml`：GitHub Pages 自动发布流程。

课程过程资料不要继续放在根目录：

- `docs/releases/`：每个版本的发布记录。
- `docs/sources/`：产品照片、植物资料、科普内容和素材核对记录。
- `docs/process/`：开发日志、技术说明、3D 接入记录和 AI 使用记录。
- `docs/archive/previous-root/`：早期根目录文件的历史归档，不参与网站运行。

## 2. 每次修改后的本地检查

在仓库根目录打开 PowerShell，按顺序执行：

```powershell
node scripts/build-static.cjs
node --check app.js
node --check data.js
node --check scripts/build-static.cjs
git diff --check
```

然后用浏览器打开 `index.html`，重点检查首页、两款产品切换、植物图鉴、成分解码、3D 入口和公众号链接。

## 3. 提交一次更新

确认页面正常后执行：

```powershell
git add -A
git commit -m "feat: describe this update"
git push origin main
```

提交信息要写清楚本次改了什么，例如：

- `feat: improve plant atlas cards`
- `fix: correct cream ingredient labels`
- `chore: organize release documents`

## 4. 发布后确认

打开 GitHub 仓库的 **Actions** 页面，确认 `Deploy static site to GitHub Pages` 显示绿色 `Success`。再打开：

`https://skybob666.github.io/-sky/`

如果浏览器仍显示旧内容，使用 `Ctrl+F5` 强制刷新。只有 Actions 成功并且网址能打开，才算完成线上发布。

## 5. 版本记录怎么留痕

每次比较大的更新都新增一份 `docs/releases/发布更新记录_vX.XX_日期.md`，记录四件事：

1. 本次修改了哪些页面或交互；
2. 使用了哪些新增或替换素材；
3. 做过哪些本地检查和线上检查；
4. 仍待老师确认或后续补充的内容。

这样根目录保持清爽，课程汇报时又能按版本回看网站如何从初版迭代到当前版。
